# 📄 단지별 식별코드 전단 (A5 양면)

> [DETAILING-PLAYBOOK.md §7.3](../DETAILING-PLAYBOOK.md) 단지 실험의 **측정 장치**.
> 이 전단이 없으면 §7.2의 전환율은 영원히 등급 D로 남는다.

---

## 1. 왜 코드가 박혀 있나

플레이북의 4주 실험은 **"어느 단지가 가장 잘 전환되는가"** 를 재는 것이다. 그런데 오프라인 전단은 기본적으로 출처가 안 잡힌다. "어디서 보셨어요?"라고 물어보는 방식은 실패한다 — 고객이 기억 못 하고, 바쁠 때 못 묻고, 물어본 걸 기록 안 한다.

그래서 **식별장치를 3중으로** 걸었다.

| 장치 | 위치 | 잡히는 경로 | 실패 시 백업 |
| --- | --- | --- | --- |
| **① QR (문자 자동작성)** | 앞면 좌하단 | 스캔 → 문자앱에 `[WJ-A1] 세차 문의합니다` 자동 입력 → **고객이 아무것도 안 해도 코드가 도착** | ②로 폴백 |
| **② 코드 배지 + 할인 유인** | 앞면 우하단 | 전화·카톡 문의 시 고객이 코드를 말함. **첫 달 1만 원 할인**이 발화 이유를 만든다 | ③으로 폴백 |
| **③ 뒷면 하단 재인쇄** | 뒷면 | 앞면이 와이퍼·오염으로 가려져도 코드가 살아남음 | — |

> 📌 **할인 유인이 핵심이다.** 유인 없이 "코드를 말씀해주세요"라고만 쓰면 아무도 안 말한다. 1만 원은 정보 값으로 싸다 — 전환 6명 기준 6만 원을 쓰고, 어느 단지에 자원을 몰아야 하는지를 알게 된다(그 판단의 가치는 §0 기준 월 115만 원이다).

---

## 2. 코드 체계

```
WJ - A 1
│    │ └─ 배포 회차 (1/2/3) — 반복 노출이 전환을 올리는지 측정
│    └─── 단지 (A/B/C)      — 어느 단지가 좋은지 측정
└──────── 지역 (운정)
```

9개 조합(A~C × 1~3차)의 QR이 `flyer.html`에 미리 내장돼 있다. 화면 상단에서 단지·회차를 고르면 앞면 QR·코드와 뒷면 코드가 동시에 바뀐다.

---

## 3. 인쇄 방법

1. `flyer.html`을 크롬으로 연다.
2. 상단에서 **단지명 / 단지 코드 / 배포 회차**를 지정한다.
3. **인쇄 / PDF 저장** 버튼 → 용지 **A5**, 배율 **100%**, **배경 그래픽 켜기**.
4. 인쇄소에 넘길 땐 **PDF로 저장한 파일**을 보낸다. HTML을 그대로 넘기면 글꼴이 바뀐다.
5. 코드별로 3~5번을 반복해 조합마다 별도 PDF를 만든다.

> ⚠️ **대량 인쇄 전 반드시:** 아이폰과 안드로이드에서 각각 QR을 한 번씩 스캔해 문자앱이 열리고 코드가 본문에 들어오는지 확인한다. `SMSTO:` 스킴 지원은 기기·스캐너마다 차이가 있다. 만약 한쪽에서 안 열려도 장치 ②·③이 살아 있어 측정은 계속된다.

## 4. 배포 기록 — 이걸 안 적으면 전부 무의미하다

QR과 코드는 **분자(문의 수)** 만 준다. 전환율을 계산하려면 **분모(배포 대수)** 가 필요하다.

> 📊 **기록표:** [`배포기록표.xlsx`](./배포기록표.xlsx) — 구글 시트에 그대로 올려 쓴다.
> **구글 드라이브 → 새로 만들기 → 파일 업로드 → 파일 우클릭 → 연결 앱 → Google 스프레드시트.**
> 수식과 서식이 그대로 넘어가고, 그 뒤로는 휴대폰 구글 시트 앱에서 현장 입력이 된다.

**손으로 적는 건 두 가지뿐이다.** 나머지는 수식이 계산한다 — 현장에서 계산하게 만들면 기록이 끊긴다.

| 시트 | 언제 | 무엇을 |
| --- | --- | --- |
| **배포기록** | 배포 당일, 차에서 바로 | 단지명 · 배포일 · **배포 대수** |
| **문의접수** | 문의가 올 때마다 한 줄 | 코드(목록 선택) · 연락처 · 유입경로 |
| | 구독이 성사되면 | 그 행의 `구독 전환`을 **Y**로 |
| **요약** | 4주 후 | 보기만 한다 — 단지별·회차별 전환율과 판정이 자동으로 뜬다 |

문의 수·전환 수·전환율·판정은 전부 자동이다. `구독 전환`에 Y를 넣는 순간 배포기록과 요약의 숫자가 함께 움직인다.

**4주 후 할 일:** 요약 시트의 **자원 집중 대상**에 뜬 단지 하나에 자원을 몰고, 나머지 두 곳에서 뺀다(플레이북 §0 초집중 시나리오). 이 시점에 §7.2 표의 등급이 <kbd>D</kbd> → <kbd>B</kbd>로 바뀐다.

> 판정 기준은 요약 시트 `B4`의 **3%** — 플레이북 §7.2 보수 시나리오의 하한값이다. 이 칸에서 바꿀 수 있다.

## 5. 파일

| 파일 | 역할 |
| --- | --- |
| `flyer.html` | **완성본 전단.** QR 9종 내장, 브라우저에서 바로 인쇄 가능 |
| `배포기록표.xlsx` | **완성본 기록표.** 구글 시트로 업로드해서 사용 |
| `flyer_template.html` | 전단 편집용 원본 (`__QR_DATA__` 자리표시자 포함) |
| `build_flyer.py` | QR 생성 + 주입 스크립트 |
| `build_sheet.py` | 기록표 생성 스크립트 |

전화번호·코드 체계를 바꾸려면 `build_flyer.py` 상단 상수를 고치고 다시 실행한다.

```bash
pip install segno
python3 build_flyer.py     # flyer_template.html → flyer.html
```
